> **本文件是本项目踩坑踩出来的。**不读它就会重犯。

## 1. 证据纪律（五条）

| # | 纪律 | 为什么 |
|---|---|---|
| **E1** | **模型自述不可作为证据。** 任何以"模型说它成功了"为输入的方法，`JUDGE_DETERMINISM = 0`，不产生分数 | 判据层的自证旁路（`evidence["verified"] is True` 由判据持有者自己写入） |
| **E2** | **凡进入结论的数字，必须直读原始工件。** 二手转述、搜索摘要、博客、榜单截图内的数字**一律不引用** | 子代理报告被独立核实的结果：**被推翻 2 次、遗漏 2 次、数据错 2 次** |
| **E3** | **负向断言必须记录检索式，并做至少两轮不同取向的检索** | 本项目已两次因此犯错；`外部组件` §8 明文要求同一条 |
| **E4** | **区分"论文说的"与"我推断的"**，推断一律加前缀（本包用 "⇒"） | 防止推断被当成事实引用 |
| **E5** | **数字必须带出处**（论文 + 表号/图号 + 版本）。跨版本冲突时**并列双值 + 版本标签**，禁止静默择一 | 项目内已知冲突：CaMeL 67/77/84；AgentPoison 0.1%/0.29%；RAGworm FPR 0.017/0.015 |

### 2.1 五轴身份与两套被废止的旧口径（**2026-09-29 变更**）

**两张卡是同一方法 ⇔ 五轴全等。** 在某轴上不同 ⇒ 计为两个方法，但须过 C11 举证。

**被废止的两套口径**（曾经并存，且逻辑方向相反——甲判可区分而丙判同一）：

| 旧口径 | 原位置 | 处置 |
|---|---|---|
| 去重方法数 `N` = `mechanism_refN` 改按五轴计，执行器是 `tools/count_identity.py` |
| `(机制, 通道, 手法类, 变换)` 四元组去重 | `docs/search-protocol.md` §47 条规则 5 | 废止。四分量仍是**出处记录**（P1/硬规矩 E），但**不再是身份** |

**为什么四分量不能当身份**：它沿着"该分开的地方"合并（`design_class`、交互形态、判据层都不在里面），沿着"未必有区别的地方"拆分（`carrier` 与 `vector` 约 5/6 重合）。判据是**可操作的**：一个字段是否属于身份，看**改变它能否改变判据判定 / `I` / `EXP` / `R_m`**。

变更提案全文见 `docs/`。

## 2. 计数纪律（方法数怎么数）

| # | 纪律 |
|---|---|
| **C1** | **变体不计入方法数。** `variant_of` 非空的卡不算 |
| **C2** | **仅靠 `transform_chain` 区分的卡不计入**，除非该变换族有实测增益证据（= **C11 在 `transform` 轴上的实例**，保留原编号以便追溯事故） |
| **C3** | **仅有载荷无执行记录的方法族不计入** |
| **C4** | **"可区分"判据（五轴）**：**注入入口**（`vector`）/ **目标资产**（`primary_asset`）/ **机制首步**（`mechanism_ref`）/ **交互形态**（`dialogue_shape`+`turns`）/ **判据层**（`judge.verifier`+`judge.evidence_layer`），五者中**至少一项不同** |
| **C11** | **任何轴上的差异，只有当该差异在来源文献中作为一次独立攻击被构造、并有独立实验数字时，才计为一个新方法**；否则并入基准卡作 `variant_of`。举证只落在**主张自己在新轴上不同**的那张卡上（字段 `distinctness_evidence`），且所引数字须满足 设计规格 §4.4 的「一个数字的最小充分集」。**找不到带对照设计的数字 ⇒ 退回变体，不得补一个数字** |
| **C5** | **分类学条目不算方法。** 表1 中 `ATK-TOOL-07`/`ATK-TOOL-08` 是 Kim SoK 的 V1/V4 定义照录（表1 字段自陈"无独立成功率数字"） |
| **C6** | **无独立论文的转述项不算方法。** 如 `ATK-MEM-04`（表1 字段自陈系"转述"） |
| **C7** | **与同表其他条目重复者不算。** `ATK-TOOL-07` ↔ `ATK-INJ-01/02/05`；`ATK-TOOL-08` ↔ `ATK-INJ-10` |
| **C8** | **双计数必须同报**：`方法-类别实例数`（目标 240）与 `去重方法数 N`。**永远不得表述为"240 种攻击方法"** |
| **C9** | **`EXT-`（自造方法）占比有上限**，实际比例必须公开在 README |
| **C10** | **各自造扩展必须标注** `provenance_kind: ext` |

## 3. 出处纪律（**本轮新增，最容易被忽略**）

| # | 纪律 |
|---|---|
| **P1** | **方法必须记录分量级出处**（`provenance_components`：机制 / 通道 / 手法类 / 变换），不得只有一个 `mechanism_ref` |
| **P2** | **切出来的方法的各分量组合，必须在某篇文献里真实出现过。** 跨文献组合须在 `composition_of` 写明是哪几篇 |
| **P3** | **"文献没做过、但理论上应该可行"的组合，一律不得进入方法库。** 这是"从文献切"与"自己编"的**唯一分界线** |

> **划分三档**（判定标准是**分量级可追溯性**，不是"有没有自己动手"）：
>
> | 档 | 做法 | 出处怎么写 | 算不算 `EXT-` |
> |---|---|---|---|
> | **档一：文献内插** | 文献已提及但未单独成篇的组合 | 指向**该文献** | 不算 |
> | **档二：跨文献组合** | A 文的机制 + B 文的通道 | `composition_of: [ref_A, ref_B]` | 不算 |
> | **档三：真发明** | 文献里没有 | 只有这档标 `ext` | **算** |

## 4. 报告纪律

| # | 纪律 |
|---|---|
| **R1** | **六态严格区分**：`pass` / `fail` / `not_applicable` / `tested_no_number` / `untested` / `inconclusive` |
| **R2** | **`untested` 不是 `R = 0`。** 是"没有分"，不是"零分" |
| **R3** | **`not_applicable` 与 `untested` 必须分开数**；混同会让覆盖率虚高 |
| **R4** | `not_applicable` **不拉低覆盖率**，也不进效力分母 |
| **R5** | **效力分母 = 适用目标数**（`preconditions ⊆ target.capabilities`），不是全部目标数 |
| **R6** | **任何效力数字的格式**：`方法 X，在目标集 {…} 上，成功 A/B，置信下界 Z%`。**不写目标集的作废** |
| **R7** | **三联数必报**：`trigger_rate` / `ASR_conditional` / `ASR_marginal`。只报边际率视为无效报告 |
| **R8** | **聚合值必须带 `index_only: true`**；`dimensions ≥ 2` 的方法必须出逐维表 |
| **R9** | **`Q` 不折减风险分，只并列展示** |
| **R10** | **禁止输出"目标总分"**（破坏 A 与泄露 C 不可通约） |

## 5. 已知失效模式（**写卡片和判据时对照自查**）

### 5.1 判据失效 19 条（A 类 13 / B 类 5 / C 类 1）

| 类 | 条数 | 性质 | 编号 |
|---|---|---|---|
| A 类 判据实现缺陷 | 13 | 判据写错了，单点可修 | D1–D12, D14 |
| **B 类 判据架构缺陷** | 5 | 写法没错，但**先聚合后判定**丢掉维度信息 | M1–M5 |
| C 类 元纪律 | 1 | 不得把失败记录成"防护良好" | C1 |

### 5.2 B 类是本项目最独特的资产（**同一结构在工程里出现 5 次**）

| | 被掩盖的维度 | 聚合值 | 真相 |
|---|---|---|---|
| M1 | 触发 | T-01 50% | 条件命中 **100%** |
| M2 | 位置 | 0.333 | 末尾 100% / 中部 **0%** |
| M3 | 模板族 | "ChatML 无增益" | B2 实测 `llama4`，渲染默认 `qwen3` |
| M4 | 单调性 | −0.111 "无退化" | 轨迹非单调，最大值为基准 **−33%，方向相反** |
| M5 | 代次 | `log_tail` 0.0 | `summary` 重算后 **1.0** |

**通则**：
```
✗ 禁止：per_axis → aggregate(标量) → verdict
✓ 要求：逐维报数 → 检验单调性/主效应 → 非单调或主效应在非聚合维度
         ⇒ 不得输出「无退化/无差异/无效果」
         ⇒ 聚合值必须带 index_only: true
```

### 5.3 其他必须知道的失效模式

| 模式 | 表现 | 防线 |
|---|---|---|
| **判据反向排序** | 一个"已验证能区分有害/良性 prompt"的分数，对实际攻击成功的 AUROC = **0.220**（成功者排在失败者之下） | 三级效度 + 逐分量对账 |
| **聚合掩盖** | 单轮 ASR 0–1% vs 15 轮 7.9–16.8%；聚合率掩盖场景级的对立弱点 | 分场景/分类别出榜 |
| **compliance-style grader 的隐含前提** | 这类判据**假设它评的 prompt 本身已经有害**，故无法比较两个有害程度不同的臂；其对照臂成功率大都是假阳性 | 审查自己判据的前提条件 |
| **借来的判据漂移** | AgentDojo 升版、StrongREJECT 改 rubric ⇒ 旧结论不可复现 | pin 版本 + 内容哈希 |
| **技术栈未锁定导致返工** | 接口契约、数据模型全部依赖技术栈 | `docs/technical-design.md` 先于 `technical-design.md` 冻结 |
