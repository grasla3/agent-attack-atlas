# 标注规程（`docs/annotation-protocol.md`）

| 项 | 值 |
|---|---|
| 状态 | **Draft v1 —— `category-taxonomy.md` §9 与 `search-protocol.md` §7 的待办** |
| 用途 | 规定 `primary_asset`（主类）与四分量标注的**双人独立标注规程**，产出 Cohen's κ |
| 为什么必须 | **`primary_asset` 是声明，不是计算**——"这个方法的终点资产是什么"需要人的判断，因此必须检验一致性 |

---

## 1. 要标注什么

| 项 | 值域 | 为什么需要人判断 |
|---|---|---|
| **`primary_asset`** | 枚举 `T01`–`T08` | 一个载荷既写业务字段又诱导读台账时，**终点算哪个**需判断 |
| `secondary_assets` | `T01`–`T08` 子集，可空 | 跨类重合的识别 |
| `vector` | 6 值 | "工具返回"与"检索文档"的边界在多跳场景下模糊 |
| `technique` | 6 值 | "自动生成"与"多轮分阶段"可同时成立 |
| `transform` | 6 值 | "编码"与"混淆"的边界 |

> **`mechanism` 不需双人标注**——它直接指向表1 条目或 `S_L*` 模板，是检索结果而非判断。

---

## 2. 抽样

| 项 | 规定 |
|---|---|
| 抽样单位 | **方法卡**（不是载荷变体） |
| **样本量** | 每类 **≥ `<待人工确认>`** 张；**全局 ≥ 30 张**（Cohen's κ 的最低对象数） |
| 分层 | 覆盖全部 8 类；每类至少 3 张 |
| 抽样方式 | 按 `Prior_SR` 分层（与 F7 的验证抽样同一套逻辑，可复用同一批卡） |
| 盲法 | 两名标注者**独立**标注，**互不可见**对方结果 |

---

## 3. 标注者要求

| # | 要求 |
|---|---|
| 1 | **两名标注者都读过** `docs/category-taxonomy.md`（类定义与谓词）与 `docs/judgment-discipline.md`（纪律） |
| 2 | 标注者**不得**是同一人；**不得**由同一会话的模型扮演两名标注者 |
| 3 | 标注前须通过**校准集**：<br>· 用 5 张**已确定**的卡做练习<br>· 两人结果**完全一致**才允许进入正式标注；不一致须先讨论并更新类定义，再重做校准 |
| 4 | 标注过程与结果**留档**（`docs/annotation-runs/<date>-<annotator>.csv`） |

---

## 4. 指标与阈值

| 指标 | 计算 | 阈值 |
|---|---|---|
| **Cohen's κ（`primary_asset`）** | 8 类，未加权 | **≥ 0.8** |
| Cohen's κ（加权，`vector` / `technique` / `transform`） | 线性加权 | ≥ 0.8 |
| 原始一致率 | 逐项 | 记录但不作判据 |

**判据（预先写死，不得事后调整）**：

```
κ ≥ 0.8  ⇒  类边界可判定，分类学通过
κ < 0.8  ⇒  【类边界有缺陷】。处理顺序：
            ① 先定位分歧集中在哪两个类之间
            ② 由分歧驱动修订 category-taxonomy.md 的类定义或谓词
            ③ 用新定义重做校准集，再重标
            ④ 不得靠"讨论后统一口径"直接消掉分歧——那会掩盖缺陷
```

> **依据**：域地图自己记的三处错误，共同模式是「**按名称/印象归类，未回原文验证**」——**错的正是标注环节**。所以 κ 必须测在标注上。

---

## 5. 分歧处理

| 分歧类型 | 处理 |
|---|---|
| **相邻类分歧**（如 T06 提取 vs T08 提取） | 检查类定义是否只差"读/写"或"资产类型"；若确实模糊，**补充判定规则**（例：终点是系统提示/工具 schema ⇒ T06；终点是台账/用户/凭据 ⇒ T08） |
| **跨轴分歧**（一个说是资产类，一个说是通道类） | 说明该卡作者把"通道"当成了"终点"。**要求改卡**，并检查同类卡是否普遍如此 |
| **无法归类** | 记为 `unassigned`，在 `docs/method-coverage.md` 单列 + `ROADMAP.md` 登记。**这可能是分类学的真缺陷**，须上报 |
| **命名分歧**（同一个类两人叫法不同） | 不是 κ 问题，是术语问题 ⇒ 检查 `spec/glossary.md` |

---

## 6. 与 CI 的关系

| 项 | 说明 |
|---|---|
| **κ 不是 CI 检查** | 它是**人工流程的产物**，不由脚本自动跑 |
| **CI 检查的是** | ① `primary_asset` 是必填枚举；② 六种 `impact_class` 全覆盖；③ 全部卡的 `primary_asset` 并集 = 8 类 |
| **κ 结果进报告** | `ValidationRun.metric = "kappa"` 或 `"weighted_kappa"`，作为效度证据之一 |
