# 01 · 领域、文献轴线与外部锚点

## 1. 我们在这个领域的什么位置

**一句话**：2026 年的生态里，考模型的、考防御的、考 harness 的、考轨迹严重度的都有；**没有一篇把"攻击方法"本身当受评对象、用经过验证的判据打分、产出方法之间可比的排名**。本项目占这个位置。

**受评单元**：攻击**方法**（不是模型、不是防御、不是轨迹、不是 harness）。

### 1.1 受评单元对照（决定我们是否还有位置）

| 工作 | 受评单元 | 判据 | 判据验没验 | 有可比排名吗 |

## 2. 四条文献轴线（**借轴，不抄类**）

| 轴 | 出处 | 取值 | 在我们这里归到哪 |
|---|---|---|---|
| **三分法风险域** | Wu et al., ACM CSUR 2026 | 数据 / 模型 / 系统 / 内容 / 衍生与应用（26 行攻击全景基于此） | 后果层对照 |
| **三类对手 + 6 攻击向量** | Kim et al., **USENIX Security 2026 SoK** | External / User-level / Internal；**V1** 间接提示注入 / **V2** 恶意数据注入 / **V3** 工具投毒 / **V4** 直接提示注入 / **V5** 模型投毒 / **V6** 记忆投毒 | **方法层的"通道"分量** |
| **7 设计维度 × 3 档** | 同上，Kim Table 1 | Input Trust / Access Sensitivity / Workflow / Action / Memory / Tool / User Interface，每维 3 档 | **目标层**（`TargetProfile.design_dimensions`） |
| **三层传播范围** | Deng et al., ACM CSUR 2025 | 组件内部 / 组件间 / 智能体间 | 方法层的"手法类"分量之一 |

### 2.1 Kim 的三类对手（**原文要点**）

| 对手 | 能力 | 自评 |
|---|---|---|
| **External** | 不能与 agent 直接交互，但能操纵 agent 会检索/处理的外部资源 | "**最受限但最现实**" |
| **User-level** | 能直接送入恶意输入；可能是恶意用户，**也可能是污染良性用户输入的第三方** | —— |
| **Internal** | 能访问 agent 组件；可能是开发者或第三方提供者 | "**实践中最难达成**" |

### 2.2 Kim 的 7 设计维度 × 3 档（**Table 1 原文**）

| 维度 | 档 1 | 档 2 | 档 3 |
|---|---|---|---|
| Input Trust | 无外部数据 | 预定义外部数据 | 任意外部数据 |
| Access Sensitivity | 无敏感数据 | 预定义敏感数据 | 任意敏感数据 |
| Workflow | 简单聊天机器人 | 固定、开发者定义 | 动态、LLM 定义 |
| Action | 仅 LLM 响应 | 响应 + 检索 | 响应 + 检索 + **执行** |
| Memory | 无记忆 | 瞬时会话记忆 | 跨会话持久记忆 |
| Tool | 无工具 | 已知工具 | 任意工具（动态发现） |
| User Interface | 纯文本 | 网页图像预览 | 可交互网页元素 |

**原文明确声明正交**：*"the dimensions are **orthogonal**; they can be used in the same agent, allowing it to have different levels along different dimensions."*

### 2.3 Kim 的维度 → 风险映射（**§4.3，可直接引用，不用自己论证**）

| 维度组 | 驱动的风险 |
|---|---|
| Input Trust / Memory / Tool | → **R1 攻击面** |
| Workflow | → **R2 / R3 / R4 模型风险** |
| Access Sensitivity / Action / User Interface | → **R5 / R6 / R7 后果风险** |

**Kim 的 R1–R7**：R1 异构不可信接口 / R2 错误指令遵循 / R3 无约束不安全数据流 / R4 幻觉与模型错误 / R5 私有数据泄露 / R6 非预期未授权动作与数据损坏 / **R7 资源耗尽与拒绝服务**。
Kim 在 Appendix A 把这套分类**对接到了 MITRE ATLAS**。

> **R7 值得注意**：Wu 的 24 威胁**没有**资源耗尽；域地图为此补建了 X2 行并引 Kim R7。**两个来源互相印证。**

### 2.4 越狱六类方法学（**方法层的"手法类"分量**）

出处：`外部组件` 行 16 明细

| | 类 | 说明 |
|---|---|---|
| ① | 手工设计 | 角色扮演 / 伪装 / 虚构场景 |
| ② | **自动生成（最主流）** | GCG / PAIR / TAP / AutoDAN / MASTERKEY / 伪装-重构 |
| ③ | 模型缺陷 | 利用生成/解码配置或模态对齐漏洞（**不改提示**） |
| ④ | **参数操纵** | 改模型权重/微调（**不改输入**）。代表：Qi et al. ICLR 2024，"仅 10 个对抗样本 + <$0.20 越狱 GPT-3.5 Turbo" |
| ⑤ | 多轮分阶段 | 把一次失败拆成多轮逐步诱导 |
| ⑥ | 具身与多模态扩展 | POEX / Agent Smith / RoboPAIR / BadRobot |

**三条最容易踩的**：

1. **`primary_asset` 是声明，不是计算**——需要你判断"这个方法的终点资产是什么"。**双人独立标注的 Cohen's κ 会检验它**；
2. **旧载荷 ID `T02_*` / `T07_*` 与新类 T02/T07 撞名**——旧 ID 保留原字符串 + `legacy_payload_id` 字段，新卡用新类编号；
