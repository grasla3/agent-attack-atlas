# 检索与入库规程（`docs/search-protocol.md`）

| 项 | 值 |
|---|---|
| 状态 | **Draft v1 —— 单类别作业的前置条件 B** |
| 用途 | 8 个攻击类别**各自扩检索**时，用同一套规程，使产出的卡**可比、可验证、可算 `EXT-` 占比** |

| 为什么需要 | 若 8 个会话各用一套标准，会出四个问题：①标准不一致 ⇒ 卡不可比 ②重复检索 ③出处无法交叉验证 ④**算不出 `EXT-` 占比** |

## 2. 纳排标准（**必须放宽，且如实标注代价**）

现有标准（`权威来源与纳排标准.md` §1–§2）是"安全四大 + NeurIPS/ICLR/ICML 主会 + 权威期刊 + 实验完整的预印本"。**该标准下现有语料只得 38 个方法，不足以支撑 240。**

### 2.1 放宽后的纳入标准（**仅适用于攻击方法侧**）

论文**至少满足以下之一**：

| # | 条件 |
|---|---|
| 1 | 正式发表于**安全四大或同级会议**（IEEE S&P / USENIX Security / CCS / NDSS） |
| 2 | 正式发表于 **NeurIPS / ICLR / ICML / ACL / EMNLP 主会或 Findings**，且研究对象包含智能体 / 工具调用 / RAG / 记忆 / 多智能体 / 具身 |
| 3 | 正式发表于 **ACM CSUR / IEEE TIFS / TDSC / TPAMI / TKDE** 等权威期刊 |
| 4 | **（放宽）发表于同行评审的 workshop**，且提供**完整威胁模型 + 可复现实验 + 公开代码或数据** |
| 5 | **（放宽）预印本**，且满足：**有独立威胁模型 ∧ 有实验数字 ∧ 攻击方法可被复现描述** |
| 6 | **（放宽）领域内被 ≥2 篇纳入文献引用的攻击工作**，即使自身 venue 不明 |

### 2.2 排除标准（**新增两条**）

沿用原标准 §2 六条，**另加**：

| # | 新增排除 |
|---|---|
| 7 | **分类学条目**：SoK / survey 中的"攻击向量定义"，本身不含实验（**依据**：容量盘点剔除 `ATK-TOOL-05~08` 四条同出一篇 Kim SoK，占表1 的 8.7%） |
| 8 | **同一工作的重复版本**：arXiv 版与会议正式版、同一系统的"攻击"与"编排原语"，**合并计一** |

### 2.3 代价（**必须如实记录**）

放宽后**来源等级必然下滑**（会有更多 B / C 级）。因此：

- 每张卡必须填 `source_grade`（`S`/`A`/`B`/`C`/`—`）与 `numeric_evidence`（`原表`/`摘要`/`无`），**两者严格分列**；
- 报告中必须给出**来源等级分布**；
- **不得**用"收录数量"掩盖"来源等级下滑"。

## 3. 检索式（每类一套，须记录并归档）

**每个类别会话必须记录自己的检索式与检索轮次**（依据 R18 / 域地图 §8：*凡负向断言必须记录检索式并做多轮不同取向的检索*）。

### 3.1 检索式模板

```
类别 T0X（<类名>），终点资产 = <资产>
检索式 1（按资产）:   "<asset>" AND (agent OR LLM) AND (attack OR injection OR poisoning)
检索式 2（按通道）:   <Kim V1–V6 关键词> AND <asset>
检索式 3（按后果）:   <impact_class 关键词> AND agent AND attack
检索式 4（按机制）:   从表1 的 ATK-* 族前缀逐个查其引用与被引
检索式 5（反向）:     从已纳入论文的参考文献与被引中回溯（snowballing）
```

### 3.2 检索轮次要求

| 轮 | 取向 | 目的 |
|---|---|---|
| 1 | 通用学术搜索 | 广撒 |
| 2 | **换一套关键词**（改按后果 / 按资产 / 按通道） | 破"检索取向单一" |
| 3 | 从已纳入论文回溯 | 补齐 |
| 4 | **venue 核验**（OpenAlex / DBLP API 等） | 确认等级 |

> **依据**：域地图的 X1 判定**因检索取向单一被推翻过两次**，最后靠 OpenAlex API 才定下来。

### 3.3 多源检索与熔断（**2026-09-29 新增，8 个类别共用**）

#### 3.3.1 为什么必须多源：一次实测的限流事故

T01 会话在第 3 轮（滚雪球）**整轮失败**，原因不是检索式写得不好，而是**单一源被整段限流**。实测记录：

| 试法 | 结果 |
|---|---|
| OpenAlex `title.search:`（不带 `mailto`） | **HTTP 429**，0.4 s 内拒绝 |
| OpenAlex 带 `mailto` 进 polite pool | **HTTP 429**，同样 0.4 s |
| 加 `User-Agent` + 指数退避重试（3→6→12→24→48→96 s） | **仍 429**；4 个种子全部 `[MISS]` |
| Semantic Scholar Graph API | **HTTP 429** |

**结论（可复用）**：退避重试**解决不了**这种限流。表现特征是"**0.5 秒内就拒绝**"——那说明是出口 IP 层面的整体拒绝，不是"你发太快"。遇到这个特征，**不要加大退避，直接换源**。


| 源 | 状态 | 在本规程里担纲什么 |
|---|---|---|
| **Crossref** | ✅ 200 | **题录真相源**（刊名/会议名/卷页/文号/被引）+ **第 3 轮反向滚雪球（参考文献）**。同样当前实现内**未观察到限流** |
| **DBLP** | ✅ 200 | **第 4 轮 venue 核验**（CS 会议/期刊归属，比聚合库准）+ venue 内定向检索 |
| **arXiv** | ✅ 200 | 预印本发现 + 版本追踪（判断"同工作多版本"，见 §47 条规则 1） |
| **Europe PMC** | ✅ 200 | 补漏（期刊题录） |
| OpenAlex | ❌ 429 | **降为可选**：仅在 `bibsearch.py health` 报其可用时才启用 |
| Semantic Scholar | ❌ 429 | 同上 |

> ⚠️ **可用性会变**。每个类别会话**开检索前必须先跑 `python tools/bibsearch.py health`**，把当次真实结果记进本类别的检索记录，**不得直接引用本节表格当"当前状态"**。

#### 3.3.3 工具：`tools/bibsearch.py`

只用 Python 标准库，无第三方包、**无 API key**。四个子命令对应本规程的四轮检索：

```bash
python tools/bibsearch.py health        # 逐源体检，判生死
python tools/bibsearch.py discover --class T01 --round 2 --queries "<检索式1>" "<检索式2>" --out 本项目取证记录
python tools/bibsearch.py refs     --doi 10.52202/079017-4136 --out 本项目取证记录
python tools/bibsearch.py verify   --doi 10.1016/j.inffus.2025.103900
python tools/bibsearch.py verify   --file dois.txt --out 本项目取证记录
```

**四条硬行为**（不是通用爬虫，是按本项目纪律写的）：

| # | 行为 | 对应纪律 |
|---|---|---|
| 1 | **熔断**：某源返回 429/403 即标记该源死亡，**本次运行不再调用**，其余源继续跑完 | 不让单源故障拖垮整轮 |
| 2 | **`sources_failed` 强制留档**，并在 stdout 打印「**结果是不完整检索，不得据此写负向断言**」 | **E3**（负向断言必须记录检索式与轮次） |
| 3 | **候选自动分可信度**（`S`/`A`/`B`/`未分级` + 是否期刊），并**剔除非合格渠道**（SSRN / Research Square / Preprints.org / TechRxiv / Zenodo / OSF 等） | §2.2 排除标准 |
| 4 | `--out` 归档**完整检索记录**（每条检索式 + 每源命中数 + 源故障清单） | §3.2（记录检索式与轮次）、可比可复算 |

**它不做什么**（避免误用）：**不判定"有没有方法"、不抽取数字、不写共享文献池**。它只产出候选与检索记录；四分量抽取（§5）与入库（§6）仍由类别会话人工完成（**E2**：数字必须直读原始工件）。

#### 3.3.4 使用要求（**8 个类别一致**）

1. 检索前跑 `health`，把结果写入本类别检索记录；
2. **四轮都要归档**（§3.2 的四轮 + 每条检索式），归档文件进 本项目取证记录；
3. 输出里的 `sources_failed` **非空时，本轮结论必须标注为"不完整检索"**；
4. 某轮**因源故障而空手**时，**不得**写成"该方向没有文献"——那是 E3 明令禁止的负向断言。

> **已知残余缺口（本规程未解决，如实登记）**：
> ① **正向被引滚雪球（谁引了我）能力削弱**——OpenAlex `cites:` 与 S2 citations 不可用时，只剩 Crossref 反向（取参考文献）与 DBLP venue 内检索两条替代；
> ② Crossref 部分记录**不开放参考文献**（实测 NeurIPS 论文 DOI `10.52202/079017-4136` 的 `reference-count=0`），此类文献反向滚雪球**不可用**，须换种子或换方向；
> ③ **SCI 收录 / JCR 分区的一手核验不在本规程能力范围**：Clarivate MJL 为 JS 单页应用、JCR 需订阅、`fenqubiao.com` 需单位账号且公告自 2026 年起不再发布分区表。第三方聚合站（LetPub / iikx / AbleSci）属**二手来源**，按 **E2** 不得作为核验值进入结论，只能标"待核"。

## 4. 去重规则

| # | 规则 |
|---|---|
| **1** | **同工作多版本合并**：arXiv ↔ 会议正式版 ↔ 期刊扩展版 ⇒ 取正式版，记录全部版本号 |
| **2** | **同工作多模块合并**：同一系统的"攻击"与"编排原语" / "辅助模块" ⇒ 合并计一 |

## 5. 分量级出处的记录格式（**硬规矩 E/F 的执行器**）

每张卡必须填：

```yaml
provenance_components:
  mechanism:  {ref: "<ATK-*|S_L*|EXT-*|LIT-<bib_id>>", source: "<表1 条目 / 模板 ID / 文献池 bib_id>"}
  vector:     {ref: "<用户输入|工具返回|检索文档|记忆写入|智能体间消息|系统提示词>",
               source: "<旧 T02 降级 / Kim2026 §4.1>"}
  technique:  {ref: "<手工设计|自动生成|模型缺陷|参数操纵|多轮分阶段|具身与多模态>",
               source: "<越狱六类方法学，域地图行16>"}
  transform:  {ref: "<无|编码|混淆|角色扮演|语言|外壳模板>", source: "<transform_chain 注册表>"}
provenance_kind: interpolation | composition | ext
composition_of: ["<ref_A>", "<ref_B>"]     # 仅 composition 时必填
```

**三档划分**（判定标准是**分量级可追溯性**，不是"有没有自己动手"）：

| 档 | 做法 | 出处怎么写 | 算不算 `EXT-` |
|---|---|---|---|
| **内插** `interpolation` | 文献已提及但未单独成篇的组合 | 指向**该文献** | 不算 |
| **组合** `composition` | A 文的机制 + B 文的通道 | `composition_of: [ref_A, ref_B]` | 不算 |
| **真发明** `ext` | 文献里没有 | 只有这档标 `ext` | **算**（上限 **20%**，比例公开在 README） |

> **硬规矩 F**：**"文献没做过、但理论上应该可行"的组合，一律不得进入方法库。** 这是"从文献切"与"自己编"的唯一分界线。

## 6. 入库流程

```
1. 检索（按 §3 的四轮，记录检索式与轮次）
2. 初筛（按 §2 的纳入标准）
3. 排除（按 §2.2 与 §4）
4. 抽取（按 §5 的四分量，逐分量记 source）
5. 判 `provenance_kind`
6. 定 `primary_asset`（声明）+ 自查谓词（§5.3 of taxonomy）
7. 写入共享文献池 docs/shared-bibliography.md（追加一行）
8. 写卡（methods/T0X/*.yaml）
9. 自检（`docs/` 第 6 节）
10. 上报异常（谓词矛盾 / 无法归类 / 容量低估）
```

**第 7 步是强制项**：不写入共享池的文献，其方法卡不得进入方法库。
